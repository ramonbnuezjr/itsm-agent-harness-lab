# v0.2 Implementation Plan

## Objective

Demonstrate governed incident creation and updates against a local ServiceNow-style mock. v0.2 must prove that write capability remains subordinate to deterministic validation, identity, authorization, approval, and audit controls.

## Constraints

- Use synthetic incidents and local files or memory only.
- Add no live ServiceNow credentials or network integration.
- Preserve the v0.1 provider boundary, retrieval, citation policy, and audit evidence.
- Keep policies deterministic and independent of model judgment.
- Deny an action whenever required context or policy evaluation is unavailable.

## Milestones

### 1. Action Contracts

**Status: complete (2026-09-11).** Typed actor, approval, incident, and proposed-action objects now live in `src/policies/action_contracts.py`. Deterministic tests cover allowed actions and fail-closed validation before any mutation tool exists.

- Define typed actor, approval, incident, and proposed-action objects.
- Define allowed fields and state values centrally.
- Add policy tests before adding executable mutation tools.

### 2. Local Incident Mock

- Implement `src/servicenow/mock_api.py` with deterministic record IDs.
- Support create, retrieve, and guarded update operations.
- Preserve before/after values for audit evidence.

### 3. Governed Creation

- Add `create_incident` with a strict tool schema.
- Require an authenticated `service_desk_agent` actor.
- Reject unknown fields, secrets, and invalid enum values.
- Audit allowed, denied, completed, and failed attempts.

### 4. Governed Updates

- Add `update_incident` after create paths are stable.
- Permit low-risk append-only work notes under role policy.
- Require bound human approval for assignment changes, P1/P2 priority, and resolution or closure.
- Reject invalid transitions and self-approval.

### 5. Scenario Evaluation

- Exercise P1 and P3 creation, routine notes, prohibited fields, invalid transitions, missing identity, approval mismatch, and execution failure.
- Record model, prompt version, policy version, tool calls, result, and reviewer judgment.
- Add lessons and changed assumptions to `docs/04-learning-log.md`.

## Acceptance Criteria

v0.2 is complete when every mutation passes through the documented decision flow, denied actions produce no state change, audit events reconstruct before/after state, the default suite remains offline and deterministic, and no path requires production credentials or data.
